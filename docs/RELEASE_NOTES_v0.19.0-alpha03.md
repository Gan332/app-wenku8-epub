# 文库 EPUB 工坊 v0.19.0-alpha03（预发布）

> 版本：v0.19.0-alpha03（versionCode 28） · 类型：**预发布 prerelease**
> 基线：v0.19.0-alpha02

这一版加**书架排序**，并修掉一个阅读统计的老问题。**无数据迁移、无配置变更**，
从 alpha02 直接覆盖安装即可。

## 这一版做了什么

### 书架排序

书架页标题下方多了「排序」入口（点开是一个轻量弹层），四档可选，**退出应用后仍然保留**：

| 排序 | 说明 |
| --- | --- |
| **最近阅读**（默认） | 读过的排在前面，没读过的按加入时间 |
| **最近加入** | 新加入的书排在前面 |
| **书名** | 按书名升序 |
| **字数** | 字数多的排在前面，未知字数（本地 EPUB 未解析）排最后 |

两条规则值得说明：

- **置顶的书在任何排序下都排在最前**。置顶是你手动标记的意图，不该被排序方式覆盖。
- **排序只影响分组内部**，「置顶 / 全部」两段结构不变。

默认档与 0.19.0 之前的行为**完全一致**——不主动改排序的话，书架顺序不会变。

### 修复：「今日」和「连续天数」不再过期

原先这两个数字是在**记录阅读时**算好存下来的，之后只有等你**下一次读书**才会更新。
后果是：

- 隔天打开应用、还没读书时，「今日」显示的其实是**昨天**的时长；
- 连续断了两天后打开，「连续天数」还显示断掉之前的旧值。

现在改成打开统计页时按**当前日期**重新计算，所以任何时候看到的都是准确的。
「最长连续」保持只增不减——历史峰值不会因为今天没读而回退。

## 内部

- 排序从 `BookshelfRepository` 移除，改由纯函数 `ui/sortBookshelf` 在展示层应用。
  原先仓库层硬编码了「置顶 → 最近阅读 → 书名」，既让用户无从选择，也让
  「设置里的排序」与「仓库的排序」成了两个真相来源。仓库现在只负责存储顺序。
- `sortBookshelf` 保证**全序且确定**：键相同时依次用书名、id 兜底。少了这层兜底，
  等值条目的顺序取决于输入顺序，DataStore 每次发射都可能不同，列表会莫名跳动。
- 新增 `data/ReadingStatsDerived.kt`：`withCurrentDay` / `streakEndingAt` 为纯函数，
  「今天是哪天」可注入，便于测试跨天与跨年。
- 新增单测：`BookshelfSortTest`（11 例）、`ReadingStatsDerivedTest`（12 例）。

## 已知问题

- **预发布版**：alpha01 的三处界面重构（书架分组 / 探索页 TabBar + 下拉刷新 / 热力图）
  仍未在真机上确认密度与手感，**本版没有改变它们**
- 书架排序**不在配置备份范围内**（配置备份只覆盖主题与阅读器设置），
  换设备时排序偏好不会跟着走
- 自建中继需要你有一个 Cloudflare 账号（免费额度即可）

## 升级说明

无数据迁移、无配置变更，从 v0.19.0-alpha02 直接覆盖安装即可。
默认排序与旧版一致；中继开关默认仍为关闭。
