# 研发与发布 SOP

## 1. MVP 边界

- 本机单用户，默认监听 `127.0.0.1:3210`。
- 仅访问用户指定、无需登录/付费/验证的公开 wenku8 页面。
- 不实现访问控制绕过、账号系统、多人协作、云同步或公网部署。
- 任务串行处理，优先保证稳定性和可诊断性。
- 任务记录和 EPUB 默认保留，由用户手动清理。

## 2. 分支模型

- `main`：始终保持可运行，仅接收通过发布门禁的提交。
- `develop`：集成开发分支。
- `feature/<issue>-<short-name>`：功能开发。
- `fix/<issue>-<short-name>`：缺陷修复。
- `docs/<short-name>`：文档变更。
- `release/<version>`：发布准备。

单人开发也必须自审；有协作者时，合并前必须完成代码审查。

## 3. 提交规范

采用 Conventional Commits：

```text
feat: 增加章节搜索
fix: 修复图片索引错位
test: 增加 EPUB 结构测试
docs: 补充用户 SOP
build: 固定 Node.js 版本
chore: 更新发布清单
refactor: 拆分解析与网络层
```

提交应聚焦单一目的，不混入无关格式化或生成文件。

## 4. 标准开发流程

1. 定义目标、验收条件、范围、非范围和风险。
2. 建立 Issue 或变更记录。
3. 从 `develop` 创建功能或修复分支。
4. 先设计接口、数据流、失败行为和兼容策略。
5. 修改代码，并同步更新测试和文档。
6. 执行 `npm run check`。
7. 执行 `npm test`。
8. 执行 `npm run smoke:epub`。
9. 涉及源站适配时执行 `npm run test:live`。
10. 自审：功能、错误处理、安全边界、兼容性和数据保留。
11. 合并到 `develop`。
12. 集成验收通过后合并到 `main`。
13. 按发布清单生成版本包、校验值和发布说明。

## 5. 代码与安全约束

- 书籍和章节 URL 必须通过 wenku8 主机白名单。
- 所有网络请求必须经过 SSRF/DNS 私网地址防护。
- 页面响应和图片必须限制大小、超时和重试次数。
- HTML、XML、文件名和任务字段在输出前必须转义或清理。
- 不实现 Cookie 注入、验证码识别、代理池、付费墙绕过或 Cloudflare 绕过。
- EPUB 必须先写临时文件，完成后原子替换为正式文件。
- 单章失败允许继续；所有章节失败不得生成空 EPUB。
- 不提交 `node_modules/`、`data/jobs/`、`output/*.epub`、`work/` 或发布临时目录。

## 6. 测试分层

### 离线测试

`npm test` 覆盖：

- URL 规范化和主机限制
- GBK/GB2312 解码
- 书籍、目录、正文和插图解析
- 相对图片 URL
- 验证页拒绝
- 私网/SSRF 防护
- 图片签名和失败索引对齐
- EPUB 3 容器、XML、manifest、封面和本地图片
- 任务参数校验、跳过失败章、全章失败、取消
- API 健康检查、UI 静态资源和错误响应
- UTF-8 下载文件名

### 真实源站测试

`npm run test:live` 使用公开页面完成：

1. 书籍元数据解析
2. 目录解析
3. 普通章节和插图章节选择
4. 后台任务生成
5. 下载接口响应
6. EPUB 内部结构和本地图片检查

源站波动时发布暂停；不得绕过访问控制来使测试通过。

## 7. 版本与发布

首个规范化版本为 `v0.1.0`。版本号遵循语义化版本：

- `PATCH`：兼容性修复
- `MINOR`：向后兼容功能
- `MAJOR`：破坏性变更

发布步骤：

```powershell
npm ci
npm run check
npm test
npm run smoke:epub
npm run test:live
npm run release:package
```

然后：

1. 按 `docs/RELEASE_CHECKLIST.md` 完成人工验收。
2. 更新 `CHANGELOG.md`。
3. 提交发布变更。
4. 创建 `v0.1.0` 标签。
5. 归档 `dist/` 中的 ZIP 和 `.sha256`。
6. 在发布说明中记录 Node.js 要求、已知限制和回滚方式。

## 8. 维护策略

- 源站 HTML 结构变化时，优先更新固定样本和解析测试。
- 依赖升级前执行完整门禁并检查锁文件变化。
- 缺陷修复优先添加可复现测试。
- 手动清理任务记录或输出前，应明确这是用户数据，不自动迁移或删除。
